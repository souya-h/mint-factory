# Receipt Haiku（設計メモ・未実装）

Jack Butcher の Credits と同じ考え方で、「支払いそのものが作品になる」版の Hash Haiku。
Tx Haiku（既存の取引を選んで取り合う方式）より、オーナーの好みはこちら。Hash Haiku の反応を見てから実装する。

## 体験

1. 買い手は、レーベルのアドレス（Basename を取れば `okonomipress.base.eth` のような名前）に決まった額のETHを送るだけ。サイトもボタンも不要で、どのウォレットからでも送れる。
2. しばらくすると、送金した取引のハッシュから生まれた詩が、送った人のウォレットに届く。
3. 詩の下には「支払った日時」が入る。自分の支払いの瞬間が、そのまま作品になる。

## 仕組み

- **支払い**：販売コントラクトが直接ETHを受け取る（`receive`）。金額が現在の価格と一致しない送金は拒否して返す（受け取らない）。受け取ったら `Paid(id, payer, amount, paidAt)` を記録する。
- **配布**：毎時のボットが新しい `Paid` を読み、その記録が載った取引のハッシュを種にして `fulfill(id, txHash)` を呼ぶ。トークンは支払った人に発行される。まとめて処理してガス代を抑える。
- **検証できる**：種が本当に支払い取引のハッシュかどうかは、誰でもチェーン上で照合できる（ミントページに照合ボタンを置く）。運営が都合のいい種を選べないことを示せる。
- **返金の保証**：配布されないまま3日経った支払いは、支払った本人がコントラクトから返金を受けられる。運営が止まっても買い手のお金は戻る。
- **値上げ**：既存の段階的値上げ（`currentPrice`）をそのまま使う。

## 作品

- 詩は Hash Haiku と同じ5-7-5の生成。
- 支払いの「秒」（0〜59）で見た目の変化を1つ選ぶ（Credits が支払いの秒で版を選ぶのと同じ発想）。例：季語を月で、背景の色味を時刻で決める。
- 下の表記は `PAID 2026-12-01 14:03:27 UTC` と支払い時刻にする。

## 注意点

- **取引所から送ると、取引所のアドレスに届く**。「自分のウォレットから送ってください」と、投稿とページに必ず書く。
- 配布はボットの実行間隔（最大1時間）だけ遅れる。届いたことを知らせる投稿を、節目ごとに出す。
- 配布のガス代は運営持ち（Baseでは1件あたりごく少額）。
- 運営の作業用ウォレットの鍵が漏れても、できるのは「支払い済みの人への配布」だけにする（勝手な無料発行はできない設計にする）。

## 実装の範囲

- 販売コントラクト：受け取り・記録・配布・返金の機能を追加（`PerPayment` モード）
- ボット：`Paid` の読み取りと `fulfill` の一括実行
- 描画：Hash Haiku に支払い時刻の表示と、秒による変化を追加
- ミントページ：送金先アドレス、現在の価格、照合ボタン
- テスト：誤った金額の拒否、二重配布の防止、返金、照合
