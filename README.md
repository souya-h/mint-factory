# mint-factory

低コストでNFTプロジェクトを量産・検証するための一式です。プロジェクト1本は「設定ファイル1枚（＋必要なら描画コントラクト1つ）」で追加できます。

- `contracts/Edition.sol`：販売用の汎用コントラクト。価格・期間・上限・売上の送金先を設定で切り替えます。
- `contracts/DailyBlock.sol` `contracts/Wrapped.sol`：絵を描くコントラクト（SVGをチェーン上で生成）。
- `projects/*.json`：プロジェクトの定義。ここを編集して push するだけで運用が変わります。
- `bot/run.js`：1時間ごとに自動実行。デプロイ、X投稿、売上の送金、撤退判定、計測を行います。
- `scripts/build-site.js`：プロジェクトごとのミントページを生成します（GitHub Pagesで無料公開）。
- `metrics/REPORT.md`：ボットが毎回更新する成績表。

## 0. 手元で動かす

Node.js 22以上が必要です。

```
npm install
npm test          # 使い捨てのローカルチェーンで、デプロイ→ミント→ボット→サイト生成を通しで検証
npm run preview daily-block    # out/daily-block.png に見本を出力
```

`npm test` は実際のネットワークにもXにも一切触れません。

## 1. ウォレットを2つ用意する

役割を分けます。こうしておくと、GitHubに置いた鍵が漏れても、失うのは少額のガス代だけです。

| | 役割 | 秘密鍵の置き場所 |
|---|---|---|
| 受取用 | 売上が届く先。コントラクトに固定され、後から変更できません | 自分の手元だけ。GitHubには**アドレスしか**入れません |
| 作業用 | デプロイと日次の操作を行う。ガス代だけ入れておく | GitHubのシークレット |

**受取用**：MetaMaskやRabbyなどのウォレットアプリで新規作成してください。表示される復元フレーズ（12語または24語）は紙に書いて保管し、写真やクラウドには残さないでください。必要なのは `0x` で始まるアドレスだけです。

**作業用**：自分のPCで次を実行すると、アドレスと秘密鍵が1回だけ表示されます。

```
npm run wallet:new
```

秘密鍵はパスワードマネージャーに保存してください。チャットやメールには貼らないでください（私にも送らないでください）。

**作業用への入金**
- テスト（Base Sepolia）：「Base Sepolia faucet」で検索すると、無料でテスト用ETHを配る公式・準公式のサイトが見つかります。
- 本番（Base）：数ドル分のETHで足ります。国内取引所でETHを買い、Baseへ直接出金できる取引所ならそのまま、できなければEthereumに出金してからBaseの公式ブリッジで移します。対応状況は取引所ごとに違うので、送金前に必ず確認してください。

## 2. X開発者アカウントを用意する

1. このプロジェクト専用のXアカウント（レーベル名義）を新規作成します。開発者アプリは後から別アカウントに移せないので、必ず専用アカウントで行ってください。
2. そのアカウントで [console.x.com](https://console.x.com) にログインし、開発者規約に同意します。
3. 「New App」でアプリを作成します。
4. アプリの権限（User authentication settings）を **Read and write** に変更します。**必ずトークン発行より先に**行ってください。後から変えた場合はトークンの再発行が必要です。
5. 「Keys and tokens」で次の4つを発行して保存します（シークレットは1回しか表示されません）。
   - API Key（Consumer Key）
   - API Secret（Consumer Secret）
   - Access Token
   - Access Token Secret
6. Billingでクレジットを少額購入し、**利用上限（spending limit）を設定**します。料金は従量制で、無料枠はありません。
7. Xアカウントの設定で、自動投稿アカウントであることを表示するラベルを付けられる場合は付けておきます。

画面の名称や料金は変わることがあるので、迷ったら [X公式ドキュメント](https://docs.x.com/fundamentals/developer-portal) を確認してください。

## 3. GitHubに置く

1. GitHubで新しいリポジトリを作り、このフォルダを push します。
   - 公開リポジトリなら Actions と Pages が無料で使えます。設定ファイル（戦略）は見えますが、シークレットは見えません。
   - 非公開にしたい場合、Actionsは無料枠で足りますが、Pagesは有料プランが必要です。
2. Settings → Secrets and variables → Actions に、次のシークレットを登録します。

| 名前 | 中身 |
|---|---|
| `DEPLOYER_PRIVATE_KEY` | 作業用ウォレットの秘密鍵 |
| `PAYOUT_ADDRESS` | 受取用ウォレットのアドレス |
| `X_API_KEY` `X_API_SECRET` `X_ACCESS_TOKEN` `X_ACCESS_SECRET` | 手順2の4つ |
| `RPC_URL` | 任意。空なら公開RPCを使います |

3. Settings → Pages → Source を「GitHub Actions」にします。
4. `config.json` を編集して push します。
   - `handle`：Xのアカウント名（@なし）
   - `chain`：最初は `baseSepolia`（テスト）。本番は `base`

以後、`bot` ワークフローが毎時17分に自動で動きます。Actionsタブから手動実行もできます。

## 無料で始める（手動投稿モード）

Xのシークレット4つを**登録しなければ**、ボットは投稿せず、投稿用の画像と文面を `queue/` フォルダに書き出します。これを自分でXに投稿すれば、Xの費用はゼロです。開発者登録（手順2）も不要です。

1. 手順3のうち、シークレットの登録を飛ばします（`teaser` の間はウォレットも不要です）。
2. ボットが `queue/` に `manual-日付-プロジェクト名.png` と `.txt` を追加していきます。GitHubのサイトやアプリから取り出せます。
3. Xで手動投稿します。Xの予約投稿機能を使えば、数日分をまとめて予約できます。投稿したファイルは `queue/` から消して構いません。
4. 反応の合計（いいね＋リポスト＋返信＋引用）をXのアナリティクスで見て、`manual-engagement.json` に書きます。

```
{ "daily-block": 12, "onchain-2026": 41 }
```

この数値で、撤退と「ready to go live」の判定が自動で行われます。書かなければ判定は保留されます。

費用が発生するのは次の2か所だけで、どちらも後回しにできます。

- **本番デプロイのガス代**：`teaser` を通過した案を Base 本番で `live` にするとき。テストネット（Base Sepolia）での確認は無料です。
- **X API**：投稿を完全自動にしたくなったとき。シークレット4つを登録すれば、その時点から自動投稿に切り替わります。

## 4. 運用の流れ

各プロジェクトは `projects/<slug>.json` の `status` で制御します。

| status | 動き |
|---|---|
| `teaser` | 見本画像の投稿だけ行う。コントラクトは出さないのでコストは投稿費のみ |
| `live` | 次回のボット実行時に自動でデプロイし、販売開始 |
| `paused` | 何もしない |

**撤退は自動です。** 判定はプロジェクトごとの設定に従います。

- `teaser`：`afterPosts` 回投稿した時点で、反応（いいね＋リポスト＋返信＋引用の合計）が `killEngagement` 未満なら終了。`promoteEngagement` 以上なら `REPORT.md` に「ready to go live」と表示されます。`config.json` の `autoDeploy` を `true` にすると、この時点で自動的に販売開始まで進みます。
- `kill`：販売開始から `afterHours` 時間で `minMints` 件に届かなければ、投稿を止めます。

売上はコントラクトに貯まり、`withdrawMinEth` を超えるとボットが受取用ウォレットへ送ります。送金先は固定なので、誰が実行しても受取用にしか届きません。

**テストから本番へ**：Base Sepoliaで一度 `live` にしてミントまで通し、問題なければ `config.json` の `chain` を `base` に変えます（本番は別のデプロイとして記録されます）。

## 5. プロジェクトを追加する

1. `projects/` のJSONをコピーして `slug` `name` `symbol` `description` `priceEth` と投稿文を書き換えます。
2. 絵を変える場合は `contracts/` に `render(uint256 seed, uint256 data)` を持つコントラクトを追加し、JSONの `renderer` にその名前を書きます。
3. `seedMode` を選びます。
   - `perMint`：1点ごとにランダム
   - `perMinter`：ウォレットごとに1点（アドレスから生成）
   - `perDay`：その日のミントは全員同じ絵（日替わり）
4. `npm run preview <slug>` で見本を確認し、`npm test` を通してから push します。

`name` `symbol` `description` には引用符・バックスラッシュ・改行を使えません（読み込み時にエラーになります）。

## 6. 費用の目安

- X：通常投稿は1件あたり約0.015ドルです。`maxPostsPerDay` が6なら、上限で月3ドル弱です。リンク入りの投稿は1件0.20ドルと高いので、ボットはリンクを付けません。ミントページのURLはプロフィールに置いてください。
- デプロイ：1プロジェクトにつきコントラクト2つです。Baseでは通常ごく少額ですが、混雑時は上がります。
- GitHub Actions / Pages：公開リポジトリなら無料です。

料金は変更されることがあります。Xの利用上限は必ず設定してください。

## 7. 知っておくべき制約

- **年間まとめの数値は検証されません。** 月別の取引数はミントページがBlockscoutの公開APIから取得し、ミント時にコントラクトへ渡します。技術に詳しい人なら数値を書き換えてミントできます。安価な記念品としては許容範囲と判断していますが、厳密さが必要なら署名サーバーが要ります。
- **年間まとめは1アドレス最大1万件まで**しか集計しません（APIの上限）。
- **日替わりブロックの絵は、その日の最初の操作で確定します。** ボットが毎日 `poke()` を呼んで確定させます。それより前にページを開いた人には仮の絵が表示されます。
- **ミント告知はリアルタイムではありません。** 毎時の実行で、節目（1、10、25、50、100件…）に達したときだけ投稿します。
- **コントラクトは監査を受けていません。** OpenZeppelinの標準実装の上に作った小さなものですが、本番投入前に第三者の確認を受けるに越したことはありません。
- 売上は課税対象です。個人と法人のどちらで受けるかは、開始前に税理士に確認してください。
